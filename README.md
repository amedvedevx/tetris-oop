# Tetris OOP

Локальный тетрис на TypeScript с игровым ядром на ООП и интерфейсом в браузере.

Сейчас работают начало и перезапуск партии: очищенное поле 10×20, первая фигура
в позиции (3, 0) её ограничивающего квадрата и preview следующего типа.
Семь фигур выдаются перемешанными мешками; просмотр не расходует очередь.
Движение, повороты, падение, пауза и сохранение рекорда добавляются следующими
фичами. Пауза пока отключена. Список клавиш остаётся видимым для знакомства
с управлением; статус поясняет, какие действия ещё не подключены.
В Storybook остаются отдельные блоки, четыре состояния страницы и пример
переключения заданных снимков; этот пример отделён от игрового ядра.

## Локальный запуск

Нужны Node.js 24.15 или новее в ветке 24.x и npm 11. `.nvmrc` выбирает Node 24.
Минимальная patch-версия нужна jsdom, используемому в интеграционных тестах.

```sh
npm ci
npm run dev
```

Приложение: [127.0.0.1:5173](http://127.0.0.1:5173).
Для библиотеки компонентов запусти в другом терминале:

```sh
npm run storybook
```

Storybook: [127.0.0.1:6006](http://127.0.0.1:6006).
Оба сервера привязаны к loopback-интерфейсу. Остановка — `Ctrl+C`.

## Сборка и проверки

Один раз установи Chromium для e2e:

```sh
npx playwright install chromium
```

Полная проверка:

```sh
npm run check
```

Команда проверяет типы и lint, запускает Vitest, собирает приложение
в `dist/`, Storybook в `storybook-static/` и отдельный e2e-вход в `.cache/e2e-app/`,
затем запускает Playwright в Chromium. Для просмотра собранного приложения: `npm run preview`
и [127.0.0.1:4173](http://127.0.0.1:4173). CI выполняет `npm ci` и `npm run check`
для PR в `develop`/`main` и при обновлении этих веток. CI устанавливает Chromium
с системными зависимостями и сохраняет HTML-отчёт, trace и снимки при сбоях.

Отдельно: `npm run test:integration` и `npm run test:e2e`. Последняя команда
сначала выполняет три сборки, затем поднимает static preview приложения на
`127.0.0.1:4180`, Storybook на `127.0.0.1:6106` и контролируемого e2e-входа на
`127.0.0.1:4181`. Эти порты должны быть свободны; существующие серверы не
переиспользуются. Все три сервера останавливаются тестовым раннером.

Локальный HTML-отчёт: `npx playwright show-report`. Повторы отключены;
браузерные ошибки и неудачные загрузки ресурсов приводят к падению теста.
Набор UI01 дополнительно проверяет составную страницу, точные данные поля/preview
и показателей, команды четырёх фаз, обновление без замены контролов, отклонение
некорректных снимков, адаптивную геометрию и читаемость при root-font 200%.
Всего — 56 проверок Vitest и 55 Playwright (54 браузерных сценария и проверка
изоляции сборки). Пример Storybook переключает
снимки данных; его тесты не являются проверкой работающей игры.
Набор F01 проверяет семь начальных фигур и preview через реальные игровые объекты,
мешки, нерасходующий peek, новый мешок при рестарте, рекорд в памяти, изоляцию
снимков и восстановление после отказа случайного источника. E2e проходит цепочку
старт/перезапуски/reload с конечными входами случайности и отдельно в обычной сборке.
Контролируемый вход использует то же ядро и UI; в production dist он не входит.
В №06 существующий production smoke приведён к доступному старту: он проверяет
начальный экран, отключённую паузу, Tab и reload; старт/мешок этим smoke не покрыты.
Дополнительные UI-регрессии проверяют центрирование самой фигуры в preview
и возвращённые пары клавиш/описаний; это не покрытие новой игровой логики.
Охват и ограничения наборов описаны в [стратегии тестирования](docs/testing.md).

Стек: TypeScript в строгом режиме, Vite, Tailwind CSS, DOM-компоненты и Storybook;
Vitest для интеграционных и отдельных юнит-тестов, Playwright для e2e. Разработка
и запуск — в этой локальной папке; сервер игры и внешние сервисы не нужны.

UI строится от базовых компонентов к блокам и странице. Все собственные компоненты
и их истории лежат плоско в `/components` в корне проекта. Весь видимый текст
проходит через `Typography`, внешний layout — через `Wrapper`.

В репозитории публикуются актуальные правила, архитектура, API и инструкции.
Внутренние обсуждения, промежуточные отчёты и локальные логи хранятся вне Git
в игнорируемых `.local/` и `.cache/`. PR содержит описание изменений и результаты
проверок без внутренних переписок и названий инструментов организации работы.

Каждая задача выполняется в отдельной ветке и завершается pull request в `develop`.
К следующей задаче переходим после ревью и принятия текущей пользователем.
Релиз в `main` проходит отдельным PR.
