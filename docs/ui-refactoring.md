# Системный рефакторинг существующего UI

Дата: 2026-10-28. Доработка задачи №02 в её текущем PR, до перехода к задаче №03.
Исходный коммит: `9e4894f0ca812bee7ba2d8a25d2ef2ca84940f82`.

## Область и исходное состояние

Проверена вся существующая UI-область: 18 файлов — шесть компонентов с шестью
файлами stories, тема, точка входа, HTML, Vite и два файла Storybook. Добавлены
три файла: внутренний resolver Wrapper и извлечённый пример кнопки с историями.
Все семь компонентов и их истории расположены плоско в корневой `components/`.
Игровых блоков и страницы игры ещё нет; пример библиотеки не является игровой фичей.

Внешних `style/className/css/sx`, CSS overrides, широкого проброса DOM-пропсов,
родительской стилизации или локальных компонентов в точке входа не обнаружено.
Переносить несуществующие overrides не требовалось. Найдены конкретные проблемы DX:

- Wrapper разрешал одновременно flex-направление и grid-колонки, молча игнорируя
  параметр другого режима; его DOM-фабрика смешивалась с длинными таблицами классов.
- Списки значений в типах и Storybook поддерживались независимо.
- Controls направления и колонок не учитывали режим Wrapper; select не отражал
  объектные адаптивные значения. Controls фигуры показывались и для пустой клетки.
- Stateful-блок кнопки со счётчиком и live-сообщением был определён внутри story-render.
- Вариант Button и тон его подписи выбирались в разных местах.

До изменений выполнен `npm run check`. Через реальный браузер сохранены DOM,
атрибуты, вычисленные стили, геометрия и JPEG-снимки всех 44 исходных историй
при 320, 768 и 1280 CSS px. Проверена активация счётчика через Enter и Space.

## Проверки результата

- `npm run check`: TypeScript, ESLint, production-сборка Vite и сборка Storybook.
- Реальные dev и production preview приложения показывают заголовок Tetris OOP
  с тем же оформлением Typography, без ошибок консоли и переполнения.
- Все 44 прежних story ID сохранены. Всего стало 47 историй семи компонентов.
- 132 сравнения исходных историй: DOM/атрибуты, выбранные computed styles
  и прямоугольники каждого элемента полностью совпали. Все 132 пары JPEG-файлов
  совпали побайтово. Горизонтального переполнения не обнаружено.
- Три новые истории проверены при 320/768/1280 CSS px. Interactive считает мышь,
  Enter и Space; Disabled остаётся нативно отключённым; длинная подпись переносится.
- Controls Wrapper: grid показывает columns и скрывает dir; возврат к flex
  показывает dir и скрывает columns. Controls BoardCell: empty скрывает piece,
  active с L создаёт доступный элемент «Активный блок L».
- В этих сценариях Controls ошибок консоли не обнаружено.

Локальные диагностические материалы находятся в игнорируемой `.cache/`:
`ui-refactor-before.json`, `ui-refactor-after.json`, каталоги снимков до/после,
`ui-refactor-check.log` и итоговый `ui-refactoring.jpg`.
Это разовый браузерный прогон, не установленное e2e/интеграционное покрытие.
Автоматические тесты остаются отдельной задачей №03 с согласованным процессом.

Ограничения: проверен текущий браузер Chromium. Firefox/WebKit, масштаб текста
200% и все возможные сочетания responsive-пропсов не проверялись. Контрольные
снимки проверяют только представленные состояния, а не все будущие потребители.
Ранее наблюдавшееся отставание Tailwind при появлении новых файлов в dev не
объявляется исправленным этим рефакторингом. Предупреждение о крупных чанках
относится к документационному runtime Storybook и существовало до изменений.
Новых ошибок поведения при проверке не обнаружено. Финальная оценка визуального
результата остаётся за пользователем при ревью PR.
