# Статические блоки и страница игры

Задача №04, ветка `codex/feat/004-game-shell` от принятой базы
`4f395adcf49f7f149cd21fa395c4159179447ae9` (merge PR №3).

В приложении появилась статическая оболочка: поле, показатели, preview, статус
и управление. Игрового ядра, генератора, часов, обработки игровых клавиш
и хранения рекорда пока нет. Все действия в обычном приложении отключены;
рядом есть пояснение. Storybook использует заданные снимки и локальные callbacks.
Это примеры отображения данных, не демонстрация работающей игры.

## Компоненты и контракты

Все компоненты и их stories находятся плоско в `components/`.
Сначала созданы StatItem, GameBoard и NextPiecePreview, затем GameStats,
GameStatus и GameControls, после них GameHeader и GamePage. Stateful-пример
обновления вынесен в отдельный GamePageInteractionDemo с собственной историей.

| Компонент | Входные данные и результат |
| --- | --- |
| StatItem | `label`, `value`: строка или число. Возвращает нативный dl с dt/dd; весь текст — Typography |
| GameBoard | Readonly-матрица CellContent, ровно 20×10; необязательное доступное имя. Отрисовывает 200 декоративных BoardCell, собственную сетку 1:2, data-x/data-y для координат. Всё поле имеет одно доступное имя |
| NextPiecePreview | PreviewPiece: kind и четыре координаты в области 4×4; либо null. Проверяет уникальность и границы координат. Геометрию не вычисляет и очередь не расходует |
| GameStats | Готовые score/lines/level/highScore. Четыре StatItem в именованной панели |
| GameStatus | Готовые phase и необязательное сообщение. Возвращает DOM с `update(phase, message?)`; live-region остаётся на месте |
| GameControls | Готовая phase и необязательный `onAction(start/pause/resume/restart)`. Без обработчика все кнопки отключены. `update(phase)` меняет подписи и доступность без замены кнопок |
| GameHeader | Фиксированные заголовок H1 и вступление. Нет публичных косметических параметров |
| GamePage | Готовый GameScreenData и необязательный onAction. Возвращаемый DOM имеет `update(data)`: поле, показатели и preview заменяются; контролы, кнопки и статус сохраняют свои узлы |
| GamePageInteractionDemo | Только пример библиотеки: callbacks переключают вручную заданные ready/running/paused-снимки. Нет движения, времени, столкновений и подсчёта результата |

GameScreenData — readonly-типы представления, не модель партии. Будущее ядро
не импортирует компоненты: его снимок будет преобразовываться в presentation.
Компоненты не читают время, случайность или localStorage, не меняют входные массивы.
До вставки обновлённых узлов GamePage проверяет форму поля и preview через их фабрики;
при отклонении этих данных предыдущие узлы остаются нетронутыми.

Нативные DOM-результаты остаются совместимыми с replaceChildren/append.
Методы update/setLabel принимают только данные, не CSS и не параметры оформления.
Callbacks устанавливаются при создании и не размножаются при update. Глобальных
обработчиков и подписок нет; удаление страницы не оставляет игровой цикл.

## Фактические проверки

- `npm run check`: типы, lint, 10 существующих интеграционных тестов,
  обе production-сборки и 13 существующих Chromium-тестов — успешно.
- 35 историй девяти новых компонентов просмотрены в реальном Storybook
  при 320/768/1280 CSS px: 105 случаев без горизонтального переполнения,
  видимого error screen и неквадратных клеток. Скрытый шаблон ошибки Storybook
  не считается ошибкой рендера; проверялась видимость и ожидаемые роли компонентов.
- В примере обновления: start показывает running, 200 клеток, четыре активных
  и 17 закреплённых; pause показывает paused; resume возвращает running.
  После каждого действия кнопка сохраняет фокус под обновлённой подписью.
  Ошибок консоли в этом сценарии не обнаружено.
- Локальное приложение на 320/768/1280 px: 200 клеток, нет горизонтального
  переполнения; ширина поля 288/320/320 px, высота приблизительно вдвое больше.
- Независимый рецензент повторил полный `npm run check` и проверил страницу
  в Chromium при 320 px с root-font 200%: горизонтального переполнения нет.
  Это проверка переполнения, не полный аудит обрезки текста или нативного text zoom.
- Снимки страницы и материалы ручной проверки сохранены локально в игнорируемой
  `.cache/004-*`. Это ручная проверка реализации, не новое автоматическое покрытие.

Каталог дополнен 35 историями новых компонентов и GameWidth/BoardWidth для Wrapper:
всего 84 истории 16 компонентов. Расширенное автоматическое покрытие новых блоков,
обновления данных, доступности и адаптивности — отдельная задача №05 после приёмки.

Независимое ревью: [результаты и проверки](reviews/004-game-shell.md).
Исходная реализация и последующие пользовательские правки получили passed,
по одному раунду и 9/10; существенных замечаний нет.

Ограничения: ручной прогон новых блоков — текущий браузер Chromium. Firefox/WebKit
и нативный browser text zoom ещё не проверены; не подменяются масштабом canvas
Storybook. Игровые клавиши, часы, генерация и подсчёт результатов не реализованы.
Нельзя утверждать игровое e2e на основании примера переключения снимков.

## Исправления после пользовательского ревью

Пользователь попросил одинаковую высоту верхних карточек, ширину и левый край
статуса по полю, нижнюю границу статуса вровень с «Управлением».
Последнее выравнивание уточнено и подтверждено пользователем.

В раскладке из двух колонок обе колонки растягиваются по общей высоте,
а крайние блоки размещаются с justify=between и минимальным gap.
Карточки показателей и preview растягиваются через собственные grid-обёртки.
Поле и статус ограничены общим maxWidth=board. Фиксированных высот, обрезки,
родительских селекторов и новых косметических props у блоков не появилось.
На узком экране блоки продолжают идти последовательно по содержимому.
