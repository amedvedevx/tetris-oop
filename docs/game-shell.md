# Блоки и страница игры

Компоненты получают готовые данные и публикуют действия через callbacks.
Обычное приложение связывает их с игровым ядром; текущие возможности описаны
в [new-game.md](new-game.md). Storybook также содержит заранее заданные снимки
и отдельный пример их переключения — он не является игровой моделью.

## Компоненты и контракты

Все компоненты и их stories находятся плоско в `components/`.
GamePage собирается из готовых блоков. Пример обновления данных
GamePageInteractionDemo имеет собственную историю.

| Компонент | Входные данные и результат |
| --- | --- |
| StatItem | `label`, `value`: строка или число. Возвращает нативный dl с dt/dd; весь текст — Typography |
| GameBoard | Readonly-матрица CellContent, ровно 20×10; необязательное доступное имя. Отрисовывает 200 декоративных BoardCell, собственную сетку 1:2, data-x/data-y для координат. Всё поле имеет одно доступное имя |
| NextPiecePreview | PreviewPiece: kind и четыре координаты в области 4×4; либо null. Проверяет уникальность и границы координат. Геометрию не вычисляет и очередь не расходует |
| GameStats | Готовые score/lines/level/highScore. Четыре StatItem в именованной панели |
| GameStatus | Готовые phase и необязательное сообщение. Возвращает DOM с `update(phase, message?)`; live-region остаётся на месте |
| GameControls | Готовая phase, необязательные `onAction(start/pause/resume/restart)` и `availability` со списками действий и подсказок. Без обработчика кнопки отключены. `update(phase)` меняет подписи и доступность без замены кнопок |
| GameHeader | Фиксированные заголовок H1 и вступление. Нет публичных косметических параметров |
| GamePage | Готовый GameScreenData, необязательные onAction, availability и statusMessage. Возвращаемый DOM имеет `update(data)`: поле, показатели и preview заменяются; контролы, кнопки и статус сохраняют свои узлы |
| GamePageInteractionDemo | Только пример библиотеки: callbacks переключают вручную заданные ready/running/paused-снимки. Нет движения, времени, столкновений и подсчёта результата |

GameScreenData — readonly-типы представления, не модель партии. Ядро
не импортирует компоненты: его снимок преобразуется в presentation.
Компоненты не читают время, случайность или localStorage, не меняют входные массивы.
До вставки обновлённых узлов GamePage проверяет форму поля и preview через их фабрики;
при отклонении этих данных предыдущие узлы остаются нетронутыми.

Нативные DOM-результаты остаются совместимыми с replaceChildren/append.
Методы update/setLabel принимают только данные, не CSS и не параметры оформления.
Callbacks устанавливаются при создании и не размножаются при update. Глобальных
обработчиков и подписок нет; удаление страницы не оставляет игровой цикл.

## Размещение и preview

На широком экране поле и статус находятся в левой колонке, показатели,
следующая фигура и управление — в правой. Статус совпадает с полной видимой
шириной поля и выровнен снизу с управлением. Верхние карточки, расположенные
рядом, имеют одинаковую высоту. На узком экране блоки идут последовательно
по содержимому; размеры не обеспечиваются обрезкой или фиксированной высотой.

Внешняя ширина поля включает рамку и ограничена общим с Wrapper токеном
20.5rem; внутренняя сетка сохраняет отношение 1:2 и квадратные клетки.

В preview центрируется ограничивающий прямоугольник четырёх занятых клеток
по обеим осям. Фон содержит 16 пустых клеток; цветной рисунок сохраняет
относительную геометрию и исходные координаты переданных данных.
Мини-поле размещено по центру карточки, заголовок и пояснение — слева.

## Доступные действия

`availability.actions` ограничивает команды, которые могут отправляться
обработчику. `availability.shortcuts` задаёт список подсказок; по умолчанию
видны все шесть. Подсказка сама по себе не подключает игровую команду.
Конфигурация фиксируется при создании; update меняет фазу, подписи и доступность.

Сценарии проверки данных, обновления, фокуса и адаптивности описаны
в [стратегии тестирования](testing.md).
