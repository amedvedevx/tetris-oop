# F01: новая партия и очередь — ревью реализации

Этот отчёт описывает первую ревизию задачи №06 (`7c71f01`). Последующие
пользовательские замечания к центрированию preview и списку клавиш закрываются
в [отдельном отчёте той же задачи](006-ui-feedback.md); исходные оценки сохранены.

Задача №06, ветка `codex/feat/006-new-game-and-queue`, база
`6044b84d3905d706c35863b947cba80726d14210` (merge принятого PR №5).
Функциональность, границы и пофайловый UI-отчёт — в [new-game.md](../new-game.md).
Формальное покрытие F01 — отдельная задача №07 после пользовательского принятия.

## Область

Новая партия/перезапуск, поле 10×20, семь исходных матриц, появление при (3,0)
ограничивающего квадрата, seven-bag и один следующий тип. Ядро не зависит от UI,
Math.random, времени или хранилища. Снимки копируют поле и координаты. Подключены
GameController, GameView и чистый адаптер данных; оформляет страницу прежняя
библиотека. Для уже работающих start/restart задана явная доступность, остальные
кнопки/подсказки не обещают несуществующего поведения. Полного игрового цикла нет.

## Обсуждение адаптации существующих тестов

До изменения тестов запущен `/root/f01_existing_test_scenarios`,
`gpt-6-astra`, high, `fork_turns: "none"`. Он изучил спецификации и исходники.
Это обсуждение миграции production smoke, не согласование полного набора F01.

Содержательные разногласия:

1. Прежний тест нажимал Enter/Space после Tab и ожидал ready, потому что все
   кнопки были disabled. Теперь это активировало бы реальный старт; агент
   отклонил сохранение этих ожиданий. Они удалены из smoke, а запуск клавишами
   проверен вручную. Автоматическое покрытие реального старта остаётся №07.
2. Tab после физического клика по disabled ненадёжен: клик может изменить точку
   последовательного фокуса. Согласован Tab на свежей странице до клика.
3. Агент предложил проверять полный ready-снимок после disabled click. Ведущий
   оспорил достаточность пустого массива занятых клеток: так пройдёт отсутствующее
   поле. Добавлены ровно 200 клеток, 200 empty и отсутствие занятых; preview —
   ровно 16 empty и без типа. Геометрия также проверяет все уникальные координаты.
4. DOM-идентичность для отсутствия действия не является отдельным контрактом:
   ElementHandle для этого smoke отклонён как лишнее требование. Идентичность
   при update по-прежнему проверяется существующей интеграцией/примером.
5. Пояснение находится в GameStatus, не в controls. Поэтому проверяется точный
   текст статуса и отсутствие kbd в controls. Отсутствие kbd не объявляется
   доказательством отсутствия клавиатурных обработчиков.

Агент явно подтвердил итоговый список; ведущий подтвердил согласие до правок.
Область — только три существующих production-smoke на 320/768/1280:

- production успешно загружается без ошибок, остаются main/H1/именованные панели,
  два aggregate img и live-region polite/atomic;
- ready: пустое поле 200/200, null-preview 16/16, метрики 0/0/0/1;
- Start доступен, Pause отключена, обе подписи верны;
- первый реальный Tab достигает Start до клика;
- физический клик по disabled Pause сохраняет полный ready-снимок;
- точное пояснение ограничений и отсутствие неподдерживаемых подсказок;
- полная геометрия и все ready-инварианты повторяются после reload.

Остальные тесты не изменены. Старые defaults компонентов и статические истории
сохраняют свои проверки. Ни один тест F01 не добавлен под видом задачи реализации;
новых проверок чувствительности игровых правил в №06 нет — они относятся к №07.
Старые 11 дефектов задачи №05 не выдаются за доказательство нового ядра.

## Фактически выполнено

- Полный `npm run check` — exit 0: TypeScript, ESLint, 36 интеграционных тестов,
  сборка приложения, сборка Storybook, 23 Chromium-теста. Число тестов не выросло.
- `git diff --check` — успешно.
- Ручной CUA-просмотр приложения на 320/768/1280: четыре активные клетки,
  один следующий тип, метрики 0/0/0/1 и без горизонтального переполнения.
- Реальный pointer start/restart; Tab → Enter и Tab → Space запускают после
  reload; клавиши перезапускают с сохранённым фокусом. Наблюдались O, T, S и J
  с координатами по правилам; preview T/L/J по локальным матрицам.
- Новые NewGameOnly-истории GameControls и GamePage просмотрены на каждой
  из трёх ширин — шесть рендеров; выбранные прежние истории проверены имеющимся e2e.
- При проверке консольных ошибок приложения и новых историй не обнаружено.

Локальные материалы: `.cache/006-check.log`, `.cache/006-manual/actions.json`,
`stories.json` и PNG. В stories.json сняты также скрытые служебные кнопки
Storybook, они не являются видимыми controls компонента; в снимках виден
реальный нативный Start/Restart и disabled Pause.

Один Enter-restart дал такую же первую пару типов — это допустимо при новом
случайном мешке. По одной картинке нельзя доказать расходование очереди или
однократность callback; это требует детерминированных проверок №07.

## Ограничения

Движение, поворот, часы, закрепление, строки, начисление очков, пауза и сохранение
рекорда не входят в №06. Ручной просмотр и существующие 59 тестов не являются
надёжным покрытием новой бизнес-логики F01. Только Chromium; Firefox/WebKit,
screen reader и нативный text zoom не проверены. CI для конкретного отправленного
коммита указывается отдельно в PR. Следующая задача — после ревью пользователя.
