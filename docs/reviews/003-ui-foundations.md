# F00: тесты локального запуска и базовых компонентов

Задача №03; ветка `codex/test/003-ui-foundations` от `develop`,
принятая база `487386ae42722b0d88ddac8b632889febb6e7d50` (merge PR №2).
Область: семь существующих компонентов и обычная production-сборка приложения.
Игровой логики пока нет. Компоненты, stories и бизнес-поведение не изменяются.

## Ревью реализации и рисков

Прочитаны все реализации, потребители и stories, тема, настройки сборки,
CI, UI-спецификация и стратегия тестов. Основные риски: интерпретация текста
как HTML, потеря HTML-семантики и доступного имени, неожиданная отправка формы,
действие disabled-кнопки, потеря фокуса, общий счётчик между экземплярами,
неверный responsive-layout, незагруженная тема, обрезка текста и неквадратная клетка.
Закрытое API оформления и использование Typography проверяются также исходниками,
а не объявляются доказанными снимками экрана.

## Обсуждение до написания тестов

Первый агент: `gpt-6-astra`, high, без истории чата, `/root/f00_test_scenarios`.
Он самостоятельно прочитал код и требования. Тесты написаны после явного согласия
на уточнённую матрицу, а не после одного формального ответа.

Содержательные разногласия и решения:

1. Корневой font-size 200% не гарантирует удвоение clamp(rem + vw) на любой ширине.
   Выбраны сценарии при 320 px с проверкой фактического размера >=1.99 от исходного.
   Это stress-проверка root font, не deviceScaleFactor и не нативный text zoom.
2. Одно scrollWidth<=clientWidth может скрыть обрезку overflow:hidden.
   Добавлены реальный текст, положительная геометрия, Range-прямоугольники строк,
   их размещение в компоненте/экране и проверка обрезающих предков.
3. Reload сбрасывает модуль и не доказывает изоляцию состояния. Проверяются два
   одновременно смонтированных счётчика и создание третьего с сохранением первых.
4. Одна disabled-story не доказывает tab order. Интеграция проверяет enabled →
   disabled → enabled; браузер отдельно проверяет физический указатель и отсутствие
   фокуса, без dispatchEvent или принудительного click по disabled.
5. UA-стили H1 способны пройти наивный CSS smoke. Production-тест одновременно
   проверяет размер/вес заголовка и сброс его/страничных отступов.
6. Сравнение цветов текста при смене viewport отклонено как слабая и лишняя
   проверка. Архитектурные ограничения проверяет ревью, Wrapper — реальная геометрия.
7. Фиксированный size сам даёт квадрат, даже без aspect-square. Добавлена fluid-story
   с проверкой доступной ширины и отношения ширины к высоте.
8. Фокус проверяется после каждого действия без повторного фокусирования, чтобы
   тест не скрывал замену DOM-узла. Space проверяется отдельно на keydown и keyup.

Для static serving переиспользуется закреплённый Vite preview с двумя outDir;
новый сервер или дополнительная зависимость для этого не вводятся.

| Браузер | Длинный текст, метрика, подпись кнопки, клавиша и Surface читаемы при 320 px и измеренном root-font 200%; нет обрезки; длинная кнопка остаётся доступной для действия |

эталонов, waitForTimeout, retries или тестов только на число вызовов.

## Проверки чувствительности

Выполняются последовательно на временно изменённых исходниках, с восстановлением
после каждого случая и при исключении. Для браузерных изменений пересобирается
соответствующий production output. Провал сборки или пустой набор не считаются
обнаружением поведенческого дефекта. Все девять дефектов обнаружены ожидаемыми
проверками; исходники восстановлены. `git diff -- components src` после восстановления
пуст. Диагностика каждого случая сохранена локально в `.cache/003-mutants/`.

| Временный дефект | Поймавшая проверка / наблюдаемый провал |
| --- | --- |
| `textContent` заменён на `innerHTML` | I1: буквальная строка отсутствует, вместо неё появился strong-элемент |
| Убрано `type="button"` | I2: настоящая форма получила submit, ожидалось 0 отправок, получена 1 |
| Игнорируется `disabled` | I3: Tab остановился на недоступной кнопке вместо следующей доступной |
| Счётчик вынесен в общий модуль | I4: второй экземпляр не показывает собственное «Нажатий: 1» |
| Для двух md-колонок используется одна | E3: первые две клетки оказались на разных строках при 768 px |
| Убран overflow-wrap | E4: текстовые Range-прямоугольники вышли за границы компонента/экрана |
| Убран aspect-square | E5: высота fluid-клетки перестала соответствовать её положительной ширине |
| Click callback выполняется дважды | E2: после мыши счётчик показал 2 вместо 1 |
| Удалён импорт темы приложения | E1: проверка reset-отступов отклонила страницу с браузерными стилями |

Для выбранных Vitest-тестов остальные намеренно исключались фильтром `-t`;
для Playwright применялся `--grep`. Это локальные проверки чувствительности,
не добавленные production-изменения и не подмена полного зелёного прогона.

## Ограничения

Первый браузер — Chromium; Firefox/WebKit пока не проверены. Root-font stress
не заменяет нативный browser text zoom и не утверждает равномерное удвоение всех
clamp-токенов на широком экране. Проверяются основные контракты и значимые
комбинации, не декартово произведение вариантов и не будущая игровая логика.
