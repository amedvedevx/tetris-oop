# Новая партия и очередь

Задача №06, ветка `codex/feat/006-new-game-and-queue`, база
`6044b84d3905d706c35863b947cba80726d14210` (принятый PR №5).

## Поведение

Приложение открывается в ready с пустым полем 10×20 и без preview. Кнопка
«Начать игру» создаёт running-партию: четыре активные клетки по исходной матрице
типа с началом ограничивающего квадрата (3, 0), один следующий тип и нулевые
очки/линии на уровне 1. Активная фигура хранится отдельно от закреплённого поля.

«Начать заново» выбрасывает остаток очереди, создаёт новый независимый мешок,
очищает поле и результаты. Случайный источник не перематывается; первая пара
типов может повториться случайно. Preview не берёт фигуру из очереди. Каждый
мешок содержит ровно I/O/T/S/Z/J/L, Fisher–Yates использует шесть значений [0,1).
Одинаковые типы на границе мешков разрешены.

Движение, повороты, время/падение, закрепление, удаление строк, пауза и запись
рекорда ещё не реализованы. Пауза отключена; подсказки неработающих клавиш скрыты,
ограничения явно показаны в статусе. Reload возвращает ready. Сейчас рекорд 0;
контроллер сохраняет переданное ему значение между стартом и перезапуском,
но localStorage пока не подключён.

## Ответственности

- `src/domain/pieces.ts` — данные семи матриц, копии локальных клеток, размер квадрата.
- `Board` — размеры и приватная матрица закреплённых клеток, отделённый снимок.
- `Tetromino` — тип и клетки в позиции появления.
- `SevenBag` — перемешивание, take и peek; готовый мешок заменяется только после
  успешного перемешивания. Ошибочный источник даёт явный RangeError.
- `GameSession` — начало/перезапуск и согласованный снимок. Новое состояние
  готовится до замены текущего; повторный start в running и restart в ready ничего
  не меняют. Снимки не раскрывают внутренние изменяемые массивы.
- `GameController` — команды и данные уровня приложения, отдельно от DOM.
- `MathRandomSource` — единственное место вызова Math.random.
- `gameScreen` — перевод снимка в UI; активные клетки накладываются только
  на новую матрицу представления, preview получает локальные координаты.
- `GameView` — существующая GamePage, команды и update. Новых визуальных
  компонентов, глобальных событий, подписок, таймеров и циклов нет.
- `main.ts` — связывание зависимостей; прежняя initialScreen удалена.

Ядро не импортирует components, DOM, часы, localStorage или тестовые библиотеки.
Наследников по типам фигур и Score-заглушки нет. Числовые результаты пока имеют
начальные значения; их расчёт появится в запланированных фичах.

## Проверки и границы покрытия

Полный локальный `npm run check` прошёл: типы, lint, 36 интеграционных тестов,
обе production-сборки, 23 Chromium-теста. Нового формального набора F01 в №06 нет:
задача №07 отдельно покрывает взаимодействие моделей, мешок и реальный старт.
Адаптация трёх существующих production-smoke предварительно согласована
с отдельным gpt-6-astra; статические контракты библиотеки не ослаблены.

Ручной просмотр через CUA: мышь запускает и перезапускает партию; Tab → Enter
и Tab → Space запускают её после reload, нативные клавиши перезапускают текущую.
Видимы четыре активные клетки и один корректный stencil preview; кнопка сохраняет
фокус после действия, метрики остаются 0/0/0/1. Приложение и обе новые истории
просмотрены при 320/768/1280, горизонтального переполнения нет.

Локальные диагностические материалы: `.cache/006-check.log`,
`.cache/006-manual/` (снимки, видимые координаты, действия и истории).
Случайная пара после одного перезапуска может совпасть: эта ручная проверка
не доказывает расходование/сброс мешка или однократный callback. Эти сценарии
будут иметь независимые детерминированные ожидания в №07. Только Chromium;
нативный text zoom и Firefox/WebKit не проверены.

Независимое ревью и обсуждение адаптации smoke: [отчёт №06](reviews/006-new-game.md).
