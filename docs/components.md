# Базовые компоненты

Область задачи №02: локальный запуск, инструменты и шесть примитивов. Блоков,
игровой страницы и бизнес-логики пока нет. Все файлы и истории лежат плоско
в корневой `components/`. Утилитарные классы не передаются снаружи.

## API

| Компонент | Назначение и публичный контракт |
| --- | --- |
| [Typography](../components/Typography.ts) | `text`, семантический `as`, `variant`, `tone`, идентификатор, доступное имя и live-режим. Создаёт текст через `textContent`, без разбора HTML. Размеры и интервалы заданы токенами; длинный текст переносится. |
| [Wrapper](../components/Wrapper.ts) | `children`, ограниченный семантический тег, flex/grid, направление, колонки, gap/padding/margin, выравнивание, ширина и предел колонки. Layout-значения поддерживают `base/sm/md/lg`, классы берутся из полных статических таблиц. `dir` не передаётся в DOM. |
| [Button](../components/Button.ts) | Строковая `label`, `variant`, `size`, `disabled`, `fullWidth`, `onClick`, идентификатор и атрибуты доступности. Нативный `button` с `type="button"`; подпись — Typography. |
| [Surface](../components/Surface.ts) | `children`, `variant`, `size`, `fullWidth`, семантический тег, идентификатор и доступное имя. Владеет фоном, рамкой, радиусом и внутренним отступом панели. |
| [BoardCell](../components/BoardCell.ts) | Пустая клетка либо `active/locked` с обязательным типом фигуры; четыре размерных режима, включая fluid. `decorative` скрывает клетку от accessibility tree, иначе доступно имя; `data-state` и `data-piece` отражают данные. |
| [KeyHint](../components/KeyHint.ts) | `key`: обозначение клавиши. Нативный `kbd`, внутри Typography. Размер зависит от содержимого, длинные обозначения переносятся. |

`style`, `className`, `class`, `css`, `sx`, объекты overrides и произвольные CSS
не являются частью API. Возвращённый DOM-элемент можно вставлять в документ
и использовать для фокуса, но потребитель не должен изменять его оформление.
Контент `children` — готовые элементы компонентов; видимые текстовые узлы
создаются через Typography. Обычная композиция не используется для overrides.

Пример композиции существующих примитивов:

```ts
const panel = Surface({
  children: [Wrapper({
    gap: 'md',
    children: [
      Typography({ as: 'h2', variant: 'heading', text: 'Партия' }),
      Button({ label: 'Начать игру', onClick: onStart }),
    ],
  })],
});
```

`theme.css` — общий Tailwind entry point и токены. Он не стилизует компоненты
глобальными или родительскими селекторами. Конфигурация приложения и Storybook
использует тот же Vite-плагин и тот же файл темы.

## Отчёт по файлам по ui-refactoring

Для всех шести файлов: прежней реализации, внешних overrides и старого API не было,
поэтому удалять или переносить старый код не требовалось. Каждый новый компонент
сразу создавался с закрытым API, собственной историей и проверкой рендера.

| Файл | Внутри компонента | Добавлено и граница ответственности | Storybook |
| --- | --- | --- | --- |
| `Typography.ts` | Шрифт, тон, адаптивный размер, line-height, переносы | HTML-семантика отдельно от варианта оформления; безопасный текст | 11 историй: все варианты текста, inverse, ошибка, длинная строка, пустой текст и HTML-подобная строка |
| `Wrapper.ts` | Только собственный layout из ограниченных токенов | Flex/grid и адаптивные значения; косметика детей не меняется | 5 историй: колонка, ряд, адаптивный ряд/сетка, пустой контейнер |
| `Button.ts` | Высота, внутренний padding, фон, рамка, focus/hover/disabled | Семантические варианты и размеры, реальное событие click; внешний отступ задаёт Wrapper | 8 историй: варианты, размер, disabled, fullWidth, длинная подпись, интерактивный счётчик |
| `Surface.ts` | Фон, рамка, радиус, тень, внутренний padding | Surface отвечает за поверхность; интервалы контента задаёт внутренний Wrapper | 6 историй: три варианта, compact, empty, длинный контент |
| `BoardCell.ts` | Цвет типа фигуры, квадратная форма, размеры и активное состояние | Только представление данных, без движения и столкновений | 8 историй: состояния, размеры, все семь типов, декоративный режим |
| `KeyHint.ts` | Рамка, фон и внутренний отступ клавиши | Семантика kbd и текст через Typography | 6 историй: пробел, стрелка, пауза, сочетание, длинная подпись, ряд стрелок |

Автоматические тесты добавляются задачей №03. Истории и ручные проверки этой
задачи не объявляются тестовым покрытием.

## Что проверено

- Чистая установка `npm ci` по lockfile: Node.js 24.19.0, npm 11.21.1.
- `npm run check`: типы, lint, сборка приложения и Storybook.
- Реальный запуск `npm run dev`, `npm run preview` и `npm run storybook`.
  Dev и production preview отображают ожидаемый проверочный заголовок;
  ошибок консоли при этой проверке не обнаружено.
- В Storybook просмотрены значимые варианты шести компонентов: Typography
  с семантикой H1/H2/P/SPAN, буквальным HTML-подобным текстом и длинной строкой;
  Button с мышью, Enter, Space, disabled и длинной подписью; тёмный Surface;
  палитра семи фигур и fluid-клетка; обычный и длинный KeyHint.
- Wrapper переключает сетку на 1/2/3 колонки при 320/768/1280 CSS px. Для
  проверенных узких историй ширина документа осталась 320 px; fluid-клетка —
  288×288 px внутри доступной области с отступами.
- Независимый код-ревьюер также выполнил `npm run check` и проверил Button
  в браузере; подробности — в [отчёте ревью](reviews/002-ui-foundations.md).

Ограничения: это выборочная ручная проверка значимых состояний, не автоматический
прогон всех 44 историй. Масштаб текста 200% и Firefox/WebKit в этой задаче
не проверялись. В dev-сеансе при добавлении новых файлов наблюдалось отставание
генерации Tailwind CSS; финальная проверка выполнена на свежем запуске Storybook.
Если после добавления компонента стиль не появился, требуется перезапуск сервера.
В сборках стили присутствуют. Проверка регрессий и расширенное покрытие — задача №03.
